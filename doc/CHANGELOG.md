# Changelog

Newest first: what changed for the person at the screen.

## 2026-10-15

- **The privacy check on a push no longer stops a new branch by mistake.** Nothing in Xsegon itself changes: this is the check that runs before Xsegon's code is pushed to GitHub (`tools\privacy-scan.js`). It took `noreply@github.com`, the address GitHub signs a pull request merged on its website with, for a personal one, and on a new branch it read every commit back to the first, so that one merge stopped every new branch. GitHub's own address is now allowed, and a new branch is checked for the commits GitHub does not have yet.

## 2026-10-14

- **Unpacking a big game no longer looks stuck.** The bar of a large disc game being unpacked jumped straight to full ("12.9 GB of 12.9 GB") and stayed there for minutes while it was still working. It now follows how far the unpacking really is.
- **New games come in by themselves.** Put games in your games folder, come back to Xsegon, and they are there: when Xsegon starts, and when its window comes back to the front after a while away, it looks in your games folders in the background and adds the new games it is sure of, naming them on the strip. Anything Scan for Games would ask you about is left for it (a possible hack, a disc set waiting for its playlist, an archive, a console with no emulator yet and the like), and Messages names those once, with a button to Scan for Games. At most one look a minute, never while a game is running. Settings > Library > Add new games by themselves turns it off, and setting up asks.
- **Setting up asks one short question at a time.** The first time Xsegon opens, it no longer shows a window of five steps. It asks "Set everything up for you?", in big words with two answers, **Yes** and **Set up by hand**. Yes goes on the same way: "Are your games here?" with the folder and how many games were found, or "Where are your games?" with **Pick the folder** and **I have none yet**. Set up by hand opens Getting started as before. Once the games are in, videos, the cheat lists and the games check are asked the same way, one at a time, in place of a window with three boxes to select.
- **ScreenScraper videos need only a free member account.** Pictures & Videos > ScreenScraper videos asked for a developer ID as well, which ScreenScraper gives only to a program's maker. Xsegon now brings its own, and the window asks only for the member name and password of a free screenscraper.fr account: type them and press Save and check. Xsegon fetches its developer ID from its website only when you press Save and check, Check the login or Fetch, and keeps a copy on this computer for when the website does not answer.
- **ScreenScraper videos come on a PC whose console speaks UTF-8.** With Windows' "Use Unicode UTF-8" option on, or a console set to UTF-8, every game ended "could not be fetched": the address reached the download tool with an invisible mark in front, and it was refused. It goes another way now.
- **A newer Games Database comes by itself.** Once a day at most, Xsegon looks for a newer copy of the LaunchBox Games Database on its release page and fetches it in the background, as Settings > Library > Games Database updates says. Until now only Check now asked.
- **An install disc or a bonus disc goes with its game, and is not taken for a game.** Some games come with a disc that is not played: Alien Isolation's Disc 1 only installs, and a Limited Edition's bonus disc holds films. Xsegon now reads such files from their names and says so in the mailbox; **Look at these files...** shows each with the game it goes with. Nothing changes until you say. Said yes, the file leaves the lists and shows in that game's new **Accompanied files** tab with its Play greyed, and the game wears the multi-disc mark. If its game is not in the library it stays in the list with Play greyed. The same tab, on any game, lets you give it a file by hand or take one back.
- **RetroArch comes with the download.** Set it all up and Get RetroArch no longer download 200 MB: the download carries RetroArch 1.22.2 as libretro publishes it, with its licence and where its source is, and setup unpacks it after the same check a download got. Only the cores your consoles need are still fetched. A carried copy that is not the tested file is refused in words, with what to do.
- **Bring in a LaunchBox library, once, with one press.** Games > Bring in a LaunchBox library... asks for your LaunchBox folder and brings in its list of games and your own play data (favourites, plays, tags). Nothing of LaunchBox's pictures, videos or sounds comes with them, nothing is shown from its folder, and nothing is written to it; Get Pictures fills the pictures in. A new copy no longer looks for LaunchBox by itself, or reads it again at every start. A folder that is not LaunchBox's is refused in words.
- **Pictures still come when the Games Database's picture server does not answer.** Get Pictures takes its pictures from the LaunchBox Games Database's own server. When a picture does not come from there, it is now asked of libretro's thumbnails instead, for a game libretro knows by its file's name, and the log says how many came that way.
- **Connect a phone works in a download.** The phone's page was left out of the download, so switching it on started nothing. It is in now.
- **The Games Database takes its updates again on a copy that once had LaunchBox.** A copy taken from LaunchBox's own database file was kept for good and never replaced by a newer one; it is now replaced by the one that comes with Xsegon, once, in a few seconds.
- **A video package goes in from Pictures & Videos > Import Xsegon Video Package.** Export Games with No videos writes the list a package is made from, as before; the message after it now says where the package goes in.

## 2026-10-13

- **One press unpacks every disc game still in an archive, and Scan for Games says so at the top.** A disc game in a .zip or a .7z was named only at the very bottom of Scan for Games, under everything else, and each one took two presses and a wait. The window now says it under its first lines: how many disc games are still packed, what they take as they are and the room free on their drive, with one button, **Unpack all** (**Unpack it**, for one). Each is checked, unpacked beside its archive and added, one after another, with the bar in the corner. The window closes on the press, unless it is also offering new games, which would go with it. The Windows Defender choice further down is the one used. A game that is in another console's folder is not moved by a press for all: its disc is read first, it stays packed, and its line says why, with its own Unpack and add button still there to move it. A spare copy of an archive whose game is already unpacked from another folder is not counted as a game waiting and is not asked for; it keeps its line further down. What is left packed on purpose is not said as a failure: the ending leads with what was unpacked and counts those apart ("2 archives unpacked, 2 games added, 1 left packed"), and when nothing was unpacked it says so in words with the reason, where it said "0 archives unpacked, 0 games added, 1 not" in red. The archives stay where they are, as before.
- **A game the online archives have no video for is not asked about again and again.** Each Videos from online archives fetch asked again for every game the one before had found nothing for, and said the same "8 games got no video" each time. A game that was looked for, with every list there is for its console read and nothing found, is now put aside: Start and the counts leave it out, and the window ends with a box, **Looked for, no video found**, where the games are folded away with why and when. **Look again** puts them back for the next Start; nothing comes back by itself. A game whose video failed to download, or whose console's list did not come, is not put aside: it is asked for again next time.
- **Videos from online archives says the consoles are selected already.** The window opens with every console selected, and each line's button read "Selected", which was taken for the thing to press: pressing it on every line left every console out, and Start then answered "select a console first". The button of a selected console now reads "✓ Selected", a line under the heading says how they stand and what a press does ("All 12 are selected. Press a console's button to leave it out, and again to take it back."), and Start with none selected says which button brings a console back.
- **Four new themes that move, and three you had that now do.** New in the round X menu and in Settings > Feel > Theme: **Space** and **Space with trees**, which stand together under Space (stars in the colours real ones come in, drifting and twinkling over a band of far light and three galaxies, one falling every few seconds, the second theme over a wood of firs along the foot of the screen), **Deep sea** (bubbles rising in water lit from above) and **Storm** (rain in thin slanted streaks, with no lightning and no sound). Three themes gained movement: Synthwave's floor rolls slowly toward you under a few stars, the Carbon themes have a few embers rising behind the panels, and under the Dracula themes a bat, or two or three, crosses in front of the games about once a minute. All of it rests when Settings > Feel > Animations is off, under High contrast and while a game runs, as the rain and the snow do.
- **The themes stand in folders, under a heading that looks like one.** The round X menu and Settings > Feel > Theme now keep the themes in five folders: Carbon, Dracula, **Nature** (Deep sea, Storm, Winter), **Neon** (Matrix, Synthwave) and Space. Xsegon and Dark stay as rows of their own, so the list is seven rows where it was ten. A copy that had Matrix, Synthwave or Winter on keeps it. The word Themes above them now stands in the highlight's colour on a band of it, so it is not taken for a row to press.
- **Videos for the consoles no set covers, cut from real playthroughs.** Pictures & Videos > Internet Archive videos is now **Videos from online archives**, and it serves consoles it could not before: Xbox, Wii, Wii U, Saturn, Dreamcast, PlayStation 2, DS, and more (PlayStation 3, Xbox 360 and the Switch among them). Where the Archive's sets leave a game without a video, Xsegon looks to World of Longplays, a community whose members record whole games and put each recording on the Internet Archive under their own names, and keeps the first 30 seconds as the game's video. Only those seconds cross the wire: the recording itself, often past a gigabyte, is never fetched, so a snap costs a few MB and a few seconds. The window is the one you know: it opens on the consoles whose games lack a video and says, per console, whether its videos come from a set, playthrough cuts, or both; Start, the corner bar and Stop are as before, and the ending says how many of the videos are playthrough cuts. Who recorded each is written in the log, and the credit to both sources is in the README under Credits. The cutter (ffmpeg, the official build with its licence beside it) comes with the download.
- **Arcade games get their videos from the Arcade Database, in the same press as every other console.** Pictures & Videos > Videos from online archives now asks the Arcade Database (adb.arcadeitalia.net, by motoschifo) first for the arcade games that have no video, whenever the Arcade console is among those selected. Its makers play and record a short video of each arcade game and give them free with no login. There is no entry and no press of its own: Start does it all. The corner shows a bar for the Arcade Database's part, which says which game it is on, and then the bar of the online archives, which are asked for whatever the Arcade Database had none of. Xsegon asks about each game by the name of its file (sf2.zip is asked about as sf2), one at a time, as the Arcade Database's makers ask of a program. A game only ever gets one video, the first found: the Arcade Database's own, or else the one of the game it is a version of, or else one from the archives. Two versions of one game share that one video. Stop on either bar stops the press; with the Arcade Database out of reach the archives are asked all the same. Its ending says how many videos came from it and names the game when it is one game that got none: the first wording ("0 of 1 arcade game with no video got one... 1 got none") was read as one video fetched.
- **A report says how Xsegon was used, and whether a controller was found.** Nothing changes on screen but two lines of the report. Help > Report a problem makes a report.txt that now lists, under its checks, each time Xsegon was open in the days of log it carries: from when to when, how long the start took, the games played, the windows opened, how much was pressed and what went wrong. Its checks have a new line, Controllers: what Windows lists as plugged in right then, and whether a controller pressed a button in Xsegon in those days. The log itself says the same three ways, since a page only hears a controller once it presses: what Windows lists as plugged in when a page opens, what the controller picture found when it closes, and which controllers pressed as the page leaves.
- **The log says what the PC was busy with when Xsegon was slow.** When a still-alive check of the page's takes three seconds or more, one line says how busy the processor and disks were and names the three programs using the most, at most once a minute. The Report a problem window says that those names can be in a report. The log also says when a RetroArch opened by itself was closed, and where Xsegon's window was when the browser paused a video.
- **One set of keyboard keys for every console.** Settings > RetroArch + Emulator Controls > RetroArch (Keyboard) has a new first entry in its Console picker, **Every console**, and opens on it. A key set there is set once for all the consoles in the list, on RetroArch's own names for the buttons; a person trying Xsegon had set the same two keys console by console, twice. A console follows it until you give that console a key of its own: choose the console to see which of its buttons each key landed on, where a row says whether its key is yours, Every console's or RetroArch's. A console's own keys are never left sharing a key because of it: a key for every console that one of your consoles already has on another button is refused, with the console named. Only the consoles in the list take part, so a computer that reads the keyboard itself is not given them. As before, the keys are handed to RetroArch when a game starts and nothing in RetroArch's own settings is changed.
- **A press on the wrong thing is answered in words.** The controller picture (Settings > View controller) said nothing when a keyboard key was pressed in it, and a person trying Xsegon pressed his game's keys there and took the silence for a fault. It now says from the start that keyboard keys light nothing in it, and a letter, a digit or an arrow pressed there is answered: that was the keyboard, this picture is a controller's, and a game's keys are in RetroArch (Keyboard). Xsegon's buttons answers the same way. And in RetroArch (Keyboard), a controller button pressed while a row waits for a key is answered too, and the wait ends with nothing changed.
- **The controller picture says when no controller is detected.** It used to say "Press any button on a controller" whether one was there or not, because a page only hears of a controller once it presses. The picture now asks Windows as it opens. With none in Windows' list it says "No controller detected. Plug one in or switch it on, then press a button on it with Xsegon in front." With one in the list that has not pressed yet it names it: "Windows sees a controller: Xbox Series X Controller. Press a button on it with Xsegon in front and it shows here." Two of one model are counted: "Windows sees 2 controllers: Xbox Series Controller (2)." Where Windows cannot be asked, the words are as they were. These are words only: a controller that presses a button is shown whatever Windows said. A server started without the piece that asks Windows now asks through a helper of a moment's life, so the picture and the report's Controllers line have a real answer there too.
- **A small x on the filter icon clears the filters.** While any filter is on, a small round x stands on the top right corner of the funnel in the search box. One press takes every filter off, with no window to open. With no filter on it is not there. It is a held-back red, whatever the theme's own highlight, and black in the themes where red would be lost: the Carbon ones, Synthwave and the Dracula ones.
- **The themes in the round X menu have a heading.** Under the line below Connect a phone, the list of themes now starts with the word Themes, so it reads as a section of its own. The heading is not a row: the bar and a controller pass it by.
- **The Controller check puts first what is looked at most.** Under This controller stand its name, its **Port** (the line that was called Place, far down the list) and its model; the maker, how it is handed over, its layout, what it sends and rumble are behind a **More** line with a Show button, out of sight until you ask. The box of buttons and sticks by number, What it sends, is now above Sticks and triggers. The chips over the picture count the controllers that are on: switch the first of two off and the one left is Controller 1, not Controller 2 (its port is still said under This controller). A controller that is switched off leaves the picture to one still on; when it was the last, the picture says "That controller is gone: switched off, unplugged or out of reach."
- **All games has a picture on a new copy.** With the platform sidebar off, the button that chooses a console showed a bare arrow on a copy with no All games picture of its own, and nobody could tell what it was. Xsegon now ships one, made from three of its console icons laid over each other, and the picker, its list and the sidebar's first row wear it. A picture of your own, or LaunchBox's, still comes first. Where no picture answers at all, the four squares that were always meant to stand there now show.
- **Get Pictures asks once more for a picture that did not come, and says what it left to you.** A picture that fails to download was skipped and the ending did not mention it. Each one is now asked for once more when the rest of the run is in, one at a time; the corner bar says so while it does. If it still does not come, the ending names it ("1 picture could not be fetched (the box of Metroid II): Get Pictures asks for it again the next time you run it"; for a logo, screenshot or background of a game that has its box it says to select the game under Already filled in Get Specific Pictures, which is where those are asked for again), and nothing more is tried by itself. The games Get Pictures was not sure of are said in two kinds: those with a likely match get one message in Messages that names them, with a **Check these games...** button that opens Get Specific Pictures on exactly those games, already looked up; those nothing was found for get a count in the ending, with Get Specific Pictures named as the place to search for them, and no message. The same games are never said twice, not even after you delete the message: the ending then names Get Specific Pictures where it would have named Messages.
- **A PC too busy to answer is no longer asked again and again.** The page asks every four seconds whether a game is running. On a PC that was choked those questions stood in line, nineteen deep in one report, each adding to the load. The page now waits for the last answer before it asks again, and gives up on one that has not come in half a minute, so the window's watchdog still hears from it. Nothing changes on a PC that answers.
- **Logging switched off writes nothing at all.** With Settings > Debug > Logging off, the window, the watchdog, the fast lane and the thumbnail build still wrote their own lines. They now ask the same setting, and the new lines above are not written, nor the work behind them started.
- **Filter by is a window of its own.** The funnel opened a panel of four columns hanging under it. It now opens a window laid out as a page of Settings: five sections that fold (Play, Ratings, Files and pictures, Hacks, Your tags), a row to each filter with its switch, and along the top what is on now, how many games that leaves and Clear all filters. A row is its name and nothing more; rest the pointer on one and it says what it does. A press anywhere on a row turns it on or off at once and the window stays up; Close or Esc puts it away. Hacks only and Leave hacks out, which could never both be on, are one row with three answers: All, Only hacks, No hacks. Your tags are small buttons, the six with the most games and never more than two lines of them; with more tags than that, a button after them ("3 more...") opens the rest as a list, so no number of tags and no long name pushes anything off the screen. With the keys the arrows walk the rows and Enter or Space presses the one they are on, and F and 2 work inside the window too; a controller walks it the same way and presses with A. View > Filter by... and a console's own menu open the same window.

## 2026-10-12

- **Cheat lists for a RetroArch that came without them.** The RetroArch that Xsegon downloads has no cheats in it, so on a new PC a game's Cheats tab had nothing to show. It now says so and offers **Get the cheat lists**: a window says what they are, how big (about 35 MB to download, about 230 MB on the disk), where from (libretro, the file RetroArch's own Update Cheats takes) and into which folder, and from there it is a bar in the corner with Stop. They go into Xsegon's own folder, never into a RetroArch of your own, and nothing is turned on: which cheats a game plays with is still a press on each. A RetroArch that has its own cheat lists is used as before and is offered nothing.
- **A game says it has cheats.** In a game's details, where "3 cheats on" stands, a game with none on now reads "19 cheats to choose from". A press on that line opens the Cheats tab.
- **Videos and cheat lists are offered beside the games check.** Set it all up asked one thing once your games were found: Run the games check? The same window now offers up to three things to select, none of them selected: videos for your games from the Internet Archive (with the size and the time for your own games), the cheat lists, and the games check. Each one you select is a line of its own on the Setting up list, with a bar and Skip. The cheat lists start at once, the videos once the names and pictures are in, and the games check stays last. With the cheat lists already on the PC and a video for every game, the window is the one it was.
- **One message that your games can have videos and cheats.** Once, when setting up ends, or at the next start for someone already set up: Messages says where videos come from and where a game's cheats are, with a button to each. It is said one time.
- **A message for the games a video fetch left out.** When Internet Archive videos has run and some games got none, Messages says how many, which consoles the Archive has nothing for, and that Skraper, a free program, can fetch them with a free ScreenScraper account. A button opens the steps, with the folder for each console. The next fetch replaces the message, and one that leaves no game out takes it away.
- **Your games on your phone, playing on the TV.** The round X's menu has a new entry, Connect a phone... Switch it on there and a phone on the home Wi-Fi can open a page of your games: point its camera at the square in its window and tap the link, and the list is on the phone, with a search and a console picker. Tap a game, tap Play on the TV, and it starts on this PC. Nothing is installed on the phone, nothing is typed, and it needs no internet. A phone let in stays let in: next time it opens its bookmark. The phone page is closed until you switch it on, and a small green phone in the top row shows for as long as it is open. Windows has to say yes once, with its shield question, and the window asks for that. The window lists the phones let in, each with Remove. A phone can see your games' names and boxes and start one; it cannot reach your settings, your files, your notes or what you have played. Settings > Window > Phone page stays open says how long it stays open: until you switch it off (as it comes), until Xsegon closes, or until no phone has used it for 30 minutes.
- **Every page of Settings has headings that fold.** Window and Screensaver showed their settings in a box with no heading, and Emulators had no boxes at all, so nothing there could be folded away as on the other pages. Now Window comes as Closing Xsegon and On a big screen, Screensaver as When it starts and What it shows, and Emulators as Add and set up and Your emulators. A press on a heading folds its part away and another opens it, as everywhere else in Settings.
- **Emulation and Show in Explorer open beside their row.** In a game's right-click menu a press on Emulation closed the menu and put a new one, with a Back row, in the top left corner of the screen. Now rest the pointer on the row and its entries open in a box attached to its side, with the menu still up behind it; a press opens it at once. The box goes to the other side of the menu where the screen ends. With the keys or a controller, Right or Enter (A) on the row goes into the box, and Left or Esc (B) comes back out. The same for a family of themes in the round X's menu. An entry that opens a window (Edit Metadata, Change Pictures) is a plain row as before, and so are Tags and Filter by.

## 2026-10-11

- **A game's menu opens the emulator that game runs in.** Right-click a game, Emulation: the last entry said Open RetroArch on every game, a Nintendo Switch one included, which RetroArch has nothing to do with. Now it names the emulator that game is started with and opens that one by itself, with no game: Open Eden on a Switch game, Open Dolphin on a GameCube or Wii one, Open PCSX2, Open RPCS3, and still Open RetroArch on a game RetroArch runs. For the things the emulator has to be open for: its settings, a controller to map, firmware or keys to put in. A game given another emulator with Set Emulator names that one.
- **The Xsegon name is the round X on a wheel, a carousel and rows.** Those views have no menu bar, so the round X and its menu (Settings, Controller, Back up what you made, the themes) could not be reached from them. There the Xsegon name at the top left now does the X's job, on the consoles screen too: it glows under the pointer, a press opens the same menu under it, and a second press puts it away. A controller reaches it at the left end of the top row. In List, Grid and Shelf the round X is where it was, and the name is a picture as before.
- **Choose which file plays, in a game's details.** A card that holds several versions of one game (the stack mark) gets a Versions tab in its details, just before Notes: every file the card stands for, with when each was last played. Press one to select it: it is kept at the press, and Play starts that file without asking. Press the selected one again to deselect it, and Play asks which one each time, as before. A version that cannot start is greyed and says why, and the facts on the left and the stack mark's box both say which one is selected.
- **A big screen is filled.** Xsegon is laid out for a 1920 x 1200 screen and did not grow: on a 1440p monitor it stood in the middle with room all round, and on a 4K one at 100% it was the middle third with small words. Now a screen bigger than 1920 x 1200 has everything drawn larger, pictures and words alike, so it reads as a 1920 x 1200 screen does: 120% on a 1440p monitor, 180% on a 4K one. Never smaller than Windows' own scaling, so a TV that Windows has at 300% stays as it is, and a screen no bigger than 1920 x 1200 is not changed at all. Settings > Window > Fill a big screen turns it off; it takes effect the next time the window opens. Only Xsegon's own window is touched, never your browser or your games.
- **Plug a TV in with Xsegon open, and it is drawn for the TV.** How large everything is drawn is decided when Xsegon's window opens. So a window opened on a laptop's screen, with a 4K TV plugged in afterwards, stayed small in the middle of the TV, and loading the page again did not help. Now Xsegon sees its screen change: the window closes and opens again by itself, about two seconds, at the new screen's size, on the view and the game you were on. The same happens the other way, when the TV is taken away. Not while a game is running: then it waits until you are back in Xsegon. A window that already fits is left alone.
- **Copy media is gone.** Settings > Library > Copy media copied LaunchBox's pictures into Xsegon's own folder. They are LaunchBox's, so the tool, its row and Settings > Paths > Media copy folder are taken out. Nothing in Xsegon copies a file of LaunchBox's now. A copy made before is yours and is still shown from where it is, pictures and videos both; nothing adds to it. A LaunchBox library shows its pictures from LaunchBox's own folder, as before.
- **The bottom bar leaves out what does not fit.** On a narrow screen (a 720p TV, a 4K TV at 300%, a small laptop) the hints along the bottom ran off both ends, the first and the last cut in half. Now the hints that fit are shown whole, in the middle, and the last ones are left out. How many fit goes with the width of the screen and with Menu text size.
- **A game's details fits a short screen.** The cover, the facts under it and the side of the box with its cartridge or disc stand one under another, which takes more height than most screens have. On a short screen (a 720p TV, a 4K TV at 300%, a laptop: a page under 950 pixels tall) the facts now stand beside the cover and everything ends above the bottom bar; on the shortest (768 and under) the side of the box and the disc share one line. A taller screen is as it was, a 1080p one too: there a game with a disc still has it below the bottom of the screen.
- **Videos from the Internet Archive, with no account.** Pictures & Videos > Internet Archive videos is for the games that have no video. The Internet Archive holds sets of game videos, a console each, free to fetch. The window opens at once on the consoles with games that lack a video, each with how many, every one selected; press a console's button to leave it out, then Start. The window closes and a bar in the corner shows how far it is, with Stop: first Xsegon asks the Archive what each set holds, then it takes the video that is surely a game's (the same matching as a video package) and fetches that one file, a few at a time. A game that has a video keeps it. At the end the strip says how many games got one, and the window, opened again, lists the games that got none and why. Xsegon carries only the list of sets, no video and no file name. It needs the internet; without it the fetch says so and nothing is changed.
- **Filter by has four more switches.** Has a manual (the games with a manual, a map or a guide), Cheats on (the games that start with cheats you selected), Hacks only and Leave hacks out (by the HACK mark; selecting one lets go of the other). They stack with the rest.
- **The list has three more columns.** Documents, Hack and Discs, under Files and pictures in the column picker. Each sorts by a press on its header, the games with nothing to say last.
- **A badge for games with a manual.** Badges > Manual or guide marks the games that have a manual, a map or a guide to open. Off until you select it.
- **One switch for all badges.** Badges > Show badges, the first entry: off, none of the menu's marks is drawn, and each keeps its own setting for when it is on again. Also Settings > View > Badges on games.
- **The Nintendo Switch and Steam have icons.** In the sidebar and the platform dropdown these two showed a small square where every other console has its picture. The Switch now has RetroArch's own icon, the two Joy-Cons in their grip, from the same set as the rest; Steam has its round mark. An icon you chose yourself still comes first.
- **The grid can show cartridges and discs.** Image Group has a sixth choice, Cartridge or disc: each tile shows what the game is played from, its cartridge or its disc, whole, in a square frame. - **The controller stays out of open panels.** With an editor or the mailbox open, A no longer starts the game hidden behind it, and B closes the panel, as Esc does. The controller also keeps the screensaver away now, which never comes up over a panel or a running game.
- **Backups with empty files restore.** A zero-byte file in a backup used to stop a restore half way.
- **Xsegon runs from any folder.** A folder name with [square brackets] in it used to stop Xsegon finding its own parts.
- **Smaller fixes.** The offline screen's countdown really counts again. A favourite that could not be saved is taken back and says why. Wait before playing keeps its half seconds. Log times are right in time zones Xsegon did not know by name. Without a Games Database yet, the check for one runs at most hourly rather than on every start, and a fetched copy that does not match its checksum is thrown away and fetched again.

## 2026-09-28

- **Xsegon's first public release.** A game front end for Windows, made for the couch: pick a console, pick a game, and it starts in RetroArch. It runs on your own PC and needs no account.
- **Getting started walks you through setup.** It opens by itself the first time: it can download RetroArch and the cores for your consoles, asks where your games are, finds them, and fills in their names, pictures and details. Tools > Getting started brings it back any time.
- **Finds your games by itself.** Tools > Scan for Games looks through the folders you choose, works out which console each game is for, and spots disc sets (an .m3u beside its discs plays as one game). Games on a drive that is unplugged simply wait until it is back.
- **Names, descriptions and pictures, built in.** Xsegon comes with a copy of the LaunchBox Games Database (about 189,000 games), so Tools > Fill in scanned games fills in each game's description, genre, release date, developer, publisher, rating, players, box art, logo, screenshot and background. Only empty fields are filled, so anything you typed stays. It keeps itself up to date: once a day at most, Xsegon fetches a newer copy in the background, or only when you press Check now if you set Settings > Library > Games Database updates to Manual. With thanks to LaunchBox and everyone who adds to their database. libretro's lists (the ones RetroArch uses) can be chosen instead in Settings > Library.
- **Five ways to browse.** A wheel, a console gallery, rows like a streaming app, a grid and a sortable list with columns you choose. Consoles first or all your games at once, a sidebar of consoles, filters, search, favourites, collections (Recently added, Two players or more) and tags of your own.
- **Made for a controller.** Everything works from a gamepad as well as the mouse and keyboard, including Settings. Video snaps play behind the chosen game, with badges for favourites, disc sets, player counts and more.
- **Plays your games properly.** Choose the core per console or per game, keep cheats, see and load save states before launching, and play Steam games next to everything else. Your own games, web games and programs can be added too.
- **The Games Database looks after itself.** If its working copy on disk is ever damaged (a crash mid-write, a disk hiccup), Xsegon notices, throws it away and rebuilds it on the next lookup, instead of failing every lookup from then on. A fetched database update that an Xsegon update has overtaken is cleaned up rather than kept for nothing, and backups leave out everything the database can rebuild or refetch by itself.
- **Tools > Runs check** starts each game in turn, quietly, and tells you which ones boot, without touching your play history.
- **Looks after itself.** Backup and restore of everything Xsegon keeps, a report of problems you can send in one click, missing games found and tidied up, and What's new (this list) inside the app.
